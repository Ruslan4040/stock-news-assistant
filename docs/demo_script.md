# Demo script (video, at most 10 minutes)

Numbers below are filled in from `evals/results/` by `python -m evals.render_docs`.

**Before recording**
- Terminal 1: `source .venv/bin/activate && streamlit run app/streamlit_app.py`
- Open in tabs: `README.md` on GitHub (the diagram renders there), `docs/REPORT.md`, `AGENTS.md`, `.claude/skills/`, `docs/crisp_dm/iterations.md`.
- The three demo cases are cached, so they answer in seconds. Live mode calls the free API and can take a minute or two: start it, keep talking, come back.

| Time | Show | Say |
|---|---|---|
| 0:00 – 0:45 | `README.md`, top | The task: a stock news awareness assistant. For a ticker and a date it shows the price trend, the news that is really about the company with a sentiment label, and one explained suggestion: buy, hold or sell, for one day or one week, with a confidence. The second half of the task is to measure honestly whether the suggestions are any good. |
| 0:45 – 1:30 | `docs/REPORT.md` §1 | Scope: 8 US large caps, headlines only, daily prices, historical and live mode, a long-only simulator. Out of scope: real trading, intraday, short selling. Main business rules: no look-ahead (news after the close belongs to the next trading day), the advisor may use only its inputs and must cite headlines, the LLM never calculates, the simulator buys only when confidence is at least 70. |
| 1:30 – 2:45 | Diagram in `README.md` | Eight components. 1: the data collector gives only what was known at decision time. 2: features are computed in Python because LLMs are bad at arithmetic. 3: the relevance filter exists because most headlines tagged with a ticker are not about the company: on average 4.120 of 10.040 even name it. 4: sentiment labels the relevant ones. 5: the advisor combines trend and news. 6: the trader measures whether confident advice makes money. 7: the judge checks explanations, in evaluation only. 8: the UI. Three LLM calls per request, all through one client with a cache, retries, JSON validation and a trace log. |
| 2:45 – 4:15 | App: NVDA, 2019-05-15, **Get advice** | Walkthrough of one input. The collector found 8 headlines. The relevance filter kept 3; point at one that was dropped and read its reason. Sentiment: 2 positive, 1 negative, 0 neutral. The advisor says `sell`, horizon `1w`, confidence 65, and cites headlines [2, 4]. The feature tiles are the same numbers the advisor received. Trader rule: action is sell, not buy → no trade. Open "What happened next": this was never shown to the pipeline. |
| 4:15 – 5:00 | Trace panel | LLM tracing: the calls of this request with prompt version, model, latency, cache flag, and the exact input and output JSON of each call. Everything is logged to `logs/llm_calls.jsonl`. |
| 5:00 – 5:45 | App: TSLA, 2026-10-22; then **Live (now)** → **Refresh now** | A date after the model's knowledge cutoff: news from Finnhub with timestamps. Then live mode: one advice per ticker per day; a refresh makes a new one only when a new relevant headline appeared. |
| 5:45 – 6:15 | Simulator tab | Equity curve of the simulator against buy & hold for each advice stream, with the trades. On the unseen period (set C) the simulator made 23 trades and returned 2.5%; buy & hold returned 0.8%. |
| 6:15 – 8:15 | Evals tab, then `docs/REPORT.md` §5 | Every component has a metric, a baseline, n and a 95% interval, and the targets were fixed in phase 1 before any eval ran. Relevance: F1 0.975 against 0.561 for keeping all headlines. Sentiment: macro-F1 0.898 on fresh headlines, where FinBERT gets 0.333. Advisor on the unseen period: hit rate 53.1% against 45.4% for always buy, but the baseline is inside the interval, so it is not proven better; in 2019 it lost to always buy. Judge: 99.8% of claims supported, and it caught 100.0% of planted false claims. Look-ahead: the model remembers 36.0% of 2019 prices within 5%, but real and anonymized inputs give the same action in 93.0% of decisions, so the advisor does not peek. Show the targets table in §5.1: which targets were met and which were not. |
| 8:15 – 9:40 | `AGENTS.md`, `.claude/skills/`, `tests/test_conventions.py`, `docs/crisp_dm/iterations.md` | How the coding agent was managed. `AGENTS.md`: CRISP-DM phases with gates, layout, coding conventions, LLM rules, data rules, evaluation rules, definition of done. `CLAUDE.md` loads it and the spec into every session. Three skills: phase log, add a component, run all evals. Rules are enforced by code, not by trust: tests with the LLM mocked, a test that fails on a function over 40 lines, a no-look-ahead test on the real data, and documents rendered from results files so no number is typed by hand. Then the loops in `iterations.md`: loop 1, four tickers had no 2019 news, so the human changed the scope; loops 2 and 3, the client blamed the model for API failures until the raw answers were read; loop 4, a new advisor prompt was tried, measured and rejected, which is a real result too. One more point: the 100 labels were drafted by the agent, and the files say so (`labeled_by`). |
| 9:40 – 10:00 | `docs/REPORT.md` §7 | Limits: 130 directional calls on the unseen period give intervals of about ± 9 points, so the advisor is not shown to beat the baselines. The trader is mostly in cash, so it is not like for like with buy & hold. Labels are an assistant draft until reviewed. Set D outcomes arrive after the next trading days. |
